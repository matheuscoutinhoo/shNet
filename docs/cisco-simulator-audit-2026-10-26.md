# Cisco compatibility and simulator completeness audit — 26 October 2026

Implementation has progressed since this baseline. See the [implementation report](cisco-implementation-2026-10-26.md) for current behavior and remaining gaps. The original measurements below are retained as historical evidence.

## Verdict and scope

**The app is a substantial educational network simulator, but it is not yet a Cisco-compatible simulator and should not be described as complete.** The engine implements considerably more than basic connectivity. The main gap is consistent, testable Cisco device behavior across configuration, operational commands, persistence, and the UI.

This review covers the current working tree based on commit `210b005ef26bf71a6efd0d3800e38f0cf008b5d7`, including the pre-existing uncommitted SQL discovery work. It examines the engine, all 49 catalog profiles, CLI modules, inspectors, protocol models, API, persistence, learning, capture/export, deployment configuration, and automated tests. It does not certify every IEEE/RFC requirement or compare against live Cisco firmware. No production deployment was changed.

The reproducible [command and profile evidence](../artifacts/cisco-completeness-audit-2026-10-26/cisco-compatibility.json) records **42 selected IOS/IOS XE checks: 5 pass and 37 expose gaps**. All **49 profiles pass basic creation, help, schema validation and snapshot/restore smoke checks**. These checks deliberately probe compatibility boundaries; their ratio is **not a product completion percentage** or proof of full profile functionality.

## Required Cisco scope

Treat the user's Cisco requirement as an acceptance requirement for applicable network equipment. Each profile needs an explicit platform family, supported release baseline, feature set, interface naming, defaults and command tree. There is no single CLI shared by every Cisco product. Cisco publishes separate [Catalyst wireless command references](https://www.cisco.com/c/en/us/support/wireless/catalyst-9800-series-wireless-controllers/products-command-reference-list.html) and [ASA command references](https://www.cisco.com/c/en/us/td/docs/security/asa/asa-cli-reference/S/asa-command-ref-S/m_show_p-show_r.html).

| Catalog profiles                                                                  | Required treatment                                                                                                                                                            |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `switch-l2`, `access`, `industrial`                                               | Catalyst/industrial switch baseline: IOS/IOS XE switching and management commands appropriate to the selected model.                                                          |
| `switch-l3`, `distribution`, `core`                                               | Explicit Catalyst IOS XE baseline; introduce a separate NX-OS profile only if Nexus behavior is intended. L3 capabilities must agree across CLI, menus and engine.            |
| `router`, `edge`, `branch`, `virtual-router`, `isp`, `nat-gateway`, `vpn-gateway` | IOS/IOS XE router baseline and documented feature differences.                                                                                                                |
| `ap`, `mesh`, `wlc`                                                               | Define autonomous/lightweight AP roles and the matching controller baseline. CAPWAP joining, management and permitted local configuration must follow that role.              |
| `sdwan-edge`, `sdwan-gateway`, `sdwan-controller`                                 | Declare the corresponding Cisco SD-WAN role and management model. The existing generic SD-WAN JSON interface is not evidence of Cisco compatibility.                          |
| `firewall`, `ngfw`, `ids`, `ips`                                                  | Declare whether these represent IOS XE zone firewall, ASA, Secure Firewall/FTD, or a generic appliance. Implement that family's behavior before labeling it Cisco-compatible. |
| `phone`, `iot`                                                                    | Keep endpoint roles. Apply Cisco phone/device behavior only when a Cisco-specific profile is selected.                                                                        |
| PCs, servers, PLC/HMI, printers, service endpoints, rack, patch panel, UPS        | Keep appropriate host/service commands and physical behavior. These do not acquire IOS CLI solely because they connect to Cisco equipment.                                    |

Current profiles expose generic `NL` models and NetOS/HostShell/ServiceShell identities, with no Cisco OS/release contract: [profiles.ts](../packages/simulation-engine/src/devices/profiles.ts), [device-commands.ts](../packages/simulation-engine/src/cli/device-commands.ts).

## Browser stability finding

All **72 distinct browser cases** in the selected appearance project eventually passed, including the complete catalog/panel sweep, mobile workflows, save/reload/recovery and the 2,000-device Worker scenario. This was not a clean first execution: 33 completed cases were preserved across controlled resumptions, then 34 of the remaining 39 passed with three workers. Five cases timed out: canvas grouping, the LAN-from-scratch flow, RSTP, LACP and automation. All five passed unchanged when rechecked with one worker.

Two timeout traces showed attempts to click devices obscured by the inspector or outside the visible canvas; others exhausted their event/result-wait deadlines. The exact cause of the concurrency sensitivity is not established. Preserve this as a Windows/local-browser test-stability finding, not proof that those network protocols are absent or that concurrent production use fails. Keep the SQL React key warning as a separate confirmed UI issue.

The [combined inventory and results](../artifacts/cisco-completeness-audit-2026-10-26/browser-summary.json) explicitly retain the five original failures and the serial outcomes. Raw evidence is in [the remaining-case run](../artifacts/cisco-completeness-audit-2026-10-26/browser.json), [serial rechecks](../artifacts/cisco-completeness-audit-2026-10-26/browser-recheck.json) and the initial pass logs. Screenshots and traces remain in ignored `.data/cisco-completeness-audit-2026-10-26`. No second complete OS-theme project was run.

## Implementation order and definition of done

Resolve the high-severity dependency findings and SQL-panel key collision as part of release qualification alongside the simulator work.

1. **Trustworthy configuration and diagnostics:** platform contracts, shared operational route/interface views, complete configuration model, running/startup lifecycle and reliable export/import. Close C02–C04 and C11 before expanding the protocol list.
2. **Core IOS/IOS XE CLI:** parser/modes/help/editing, interface/VLAN/trunk/STP/LACP, management gateway, OSPF/BGP/RIP, ACL/NAT and device access. Close C01 and C05–C10 with per-command tests that assert resulting traffic and UI state.
3. **Common Cisco laboratories:** CDP/LLDP, HSRP, switching protections, static-route recursion/AD/ECMP and selected dynamic IPv6/EIGRP coverage. Add failure, recovery and persistence exercises.
4. **Advanced profiles:** family-specific wireless/security/SD-WAN, multicast, fabric/MPLS enhancements, remaining management/capture and service-HA work, each with an explicit acceptance boundary.

A profile is ready only when its declared commands, context/privileges, defaults, packet effects, timers/convergence, operational output, UI, save/reload and configuration round trips agree. Unsupported commands must be distinguishable from supported-but-misconfigured commands. Maintain a reference transcript suite against the selected Cisco documentation and, when available, legally provided Cisco lab images or hardware. No firmware execution is required to build a behavioral simulator.
