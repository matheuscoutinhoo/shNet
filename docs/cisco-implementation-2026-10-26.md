# Cisco simulator implementation — 26 October 2026

This is an implementation update to the [original completeness audit](cisco-simulator-audit-2026-10-26.md). It does **not** certify the simulator as complete or as Cisco firmware.

The reproducible command audit improved from **5/42 to 41/42 passing checks**, with all **49 device-profile smoke checks passing**. The remaining focused check is native SSH/VTY line configuration. These are selected boundary checks, **not a completion percentage**. Protocol behavior has separate packet-level tests; advanced features remain outside this command inventory.

Evidence is retained under [the implementation artifact directory](../artifacts/cisco-implementation-2026-10-26/). The engine contract is `2026.10.26.1`.

The subsequent [six-site enterprise validation](global-enterprise-validation-2026-10-26.md) expands this selected command inventory. It identifies a `no switchport`/Rapid PVST regression, rejected multilayer-switch DHCP relay, and broader native-workflow/fidelity gaps. Its findings remain open; the passing checks below do not supersede that audit.

## Startup scope and limits

Startup replay currently supports the core router/switch configuration represented by the native exporter, including IPv4/VRFs, supported ACL/NAT/routing/STP settings, EtherChannel (LACP), IOS DHCP server pools, discovery, HSRP and enable secrets. Saving first replays the configuration into an isolated draft, validates it and compares its exported configuration. The live device is updated only after validation succeeds; a rejected replay names the offending startup-config line. Reload is also applied atomically and renegotiates copper links without changing native port speeds.

The first power-on of a newly placed catalog device preserves its initial offline provisioning and assigned name, so devices remain identifiable while constructing the lab. Catalog switches boot with Rapid PVST+ unless spanning tree was configured. Subsequent managed power cycles load startup configuration. Startup erasure retains its reset behavior.

`reload` follows the IOS dialog: when booting from startup-config would lose part of the running configuration it asks `System configuration has been modified. Save? [yes/no]:`, then `Proceed with reload? [confirm]` (Enter or `y` confirms; any other answer, or Ctrl-C, cancels).

`write memory` explicitly refuses unsupported device/port configuration, such as advanced services, wireless or tunnels, instead of silently dropping it. Custom static-route metrics are also refused. **Whole-laboratory save/export continues to preserve the complete simulator snapshot**; it is separate from the simulated IOS startup lifecycle. A managed power cycle deliberately discards unsaved configuration. Advanced startup coverage remains unfinished.

The declared core factory target is an educational **IOS/IOS XE 17.12 behavior subset**. The app executes its own event-driven model. It does not run vendor firmware, and the declaration does not certify every command, default, platform feature or on-wire protocol. Wireless controllers/APs, ASA-like firewalls, Nexus and endpoint operating systems still need their own explicit family contracts.

## Remaining work

1. **Native remote terminal access:** console/VTY line configuration, local users, SSH/Telnet sessions over simulated transport, timeouts and session privileges, integrated with the existing AAA model. `enable secret` is implemented; it does not provide SSH or line login.
2. **Complete native configuration coverage:** secure, reproducible startup/export for advanced services; RIP network/passive-interface workflows; complete BGP address-family/policy behavior; MST region mode; native PAT/numbered ACLs and family-specific firewall commands. Some existing features still use educational DSL/JSON extensions.
3. **Protocol breadth and fidelity:** ECMP and tracked static routes, HSRP authentication/IPv6/object tracking, additional routing and multicast protocols, and the other industrial/security/service gaps in the original audit. HSRP currently has no binary PCAP codec; unsupported packets are reported as excluded.
4. **Platform contracts and UI coverage:** document each applicable catalog profile's precise Cisco family, defaults and command tree; expand protocol inspectors and guided labs for the new features; compare supported behavior against captured Cisco/reference scenarios.
5. **Original audit backlog:** universal PCAP coverage, native SSH/SNMPv3, broader IPv6/industrial protocols and other remaining items remain open unless explicitly covered above.
